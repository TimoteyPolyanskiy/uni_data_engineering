# Реєстр проблем якості даних (Data Quality Findings)
**Пакет даних:** CityFlow S08 (cityflow_S08_base_v1.zip)
**Дата аудиту:** 2026-10-03

## 1. Повні дублікати рядків (Full Row Duplicates)
- **Файли та поля:**
  - `customers.csv` (ключ: `customer_id`)
  - `merchants.csv` (ключ: `merchant_id`)
  - `products.csv` (ключ: `product_id`)
  - `orders.csv` (ключ: `order_id`)
- **Кількість рядків:** по 1 дубльованому рядку в кожному файлі (всього 4 записи).
- **Приклади ID:** `S08-C000504`, `S08-M00009`, `S08-P000219`, `S08-O0000683`.
- **Можливий вплив:** Штучне завищення агрегатів виручки, дублювання транзакцій та збій накладання обмежень Primary Key (`UNIQUE`) у реляційній базі.
- **Запропонована дія:** Дедуплікація під час перенесення у Staging-шар (`DROP DUPLICATES` за первинним ключем із збереженням першого входження).

## 2. Порушення референційної цілісності (Orphan Foreign Keys)
- **Файли та поля:**
  - `orders.customer_id` -> відсутній у `customers.customer_id` (1 рядок, `order_id`: `S08-O0004825`)
  - `orders.merchant_id` -> відсутній у `merchants.merchant_id` (1 рядок, `order_id`: `S08-O0005136`)
  - `products.merchant_id` -> відсутній у `merchants.merchant_id` (1 рядок, `product_id`: `S08-P000331`)
- **Кількість рядків:** 3 записи сумарно.
- **Можливий вплив:** Падіння `FOREIGN KEY` констрейнтів під час завантаження в PostgreSQL; втрата даних або поява `NULL` при виконанні `INNER JOIN` / `LEFT JOIN` у звітності.
- **Запропонована дія:** Маршрутизація сирітних записів у карантинну таблицю (Dead Letter Queue / Quarantine Table) до з’ясування джерела, або підстановка технічного сурогату `UNKNOWN_RECORD`.

## 3. Неконсистентний формат категоріального поля (orders.currency)
- **Файли та поля:** `orders.csv`, поле `currency`.
- **Проблема:** Поруч зі стандартними кодами `UAH`, `EUR`, `USD` зафіксовано значення `UA H` із пробілом.
- **Кількість рядків:** 1 запис.
- **Можливий вплив:** Фрагментація фінансових звітів при групуванні `GROUP BY currency`, некоректне відображення валют у BI-дашбордах.
- **Запропонована дія:** Строкова нормалізація у шарі очищення: видалення пробілів (`REPLACE(currency, " ", "")`) або регулярний вираз для зведення до стандарту ISO 4217.

## 4. Порушення доменних обмежень вартості (products.unit_price_uah)
- **Файли та поля:** `products.csv`, поле `unit_price_uah`.
- **Проблема:** Непозитивна ціна товару (значення <= 0).
- **Кількість рядків:** 1 запис.
- **Приклад ID:** Товар `product_id`: `S08-P000331` (або супутній за аномальною ціною).
- **Можливий вплив:** Помилки в розрахунку виручки закладу та маржинальності сервісу, порушення умови `CHECK (unit_price_uah > 0)`.
- **Запропонована дія:** Перевірка бізнес-правил (чи це промо-акція/подарунок), заміна на `NULL` із позначкою валідації або ізоляція в карантинний набір.

## 5. Пошкоджені значення дат (orders.created_at)
- **Файли та поля:** `orders.csv`, поле `created_at`.
- **Проблема:** Рядки містять невалідні часові мітки, які не парсяться у формат дати (`errors="coerce"` повертає `NaT`).
- **Кількість рядків:** 2 записи.
- **Можливий вплив:** Втрата точності при часовому аналізі замовлень, збій при парсингу в `TIMESTAMPTZ` у реляційній БД.
- **Запропонована дія:** Спроба відновлення через супутні логи чи поля оновлення; за неможливості — збереження сирого значення в аудит-полі та встановлення `NULL` для аналітичної моделі.

## 6. Пропущені значення контактних даних (customers.phone)
- **Файли та поля:** `customers.csv`, поле `phone`.
- **Проблема:** 5 пропущених значень (`NaN`).
- **Кількість рядків:** 5 записів.
- **Можливий вплив:** Неможливість авторизації через SMS чи зв’язку кур’єра з клієнтом при адресній доставці.
- **Запропонована дія:** Прийняти пропуск як допустимий на рівні моделі (якщо телефон не є обов’язковим для веб-реєстрації), але прапорувати профіль клієнта як `unverified_phone`.
