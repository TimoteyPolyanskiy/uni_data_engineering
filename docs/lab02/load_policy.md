# Політика завантаження, валідації та карантину (CityFlow S08)

## 1. Схема шарів даних
- **stg (Staging):** точна копія CSV-файлів, усі стовпці у форматі `TEXT`. Гарантує імпорт без втрати рядків і збоїв парсингу.
- **core (Domain model):** типізована реляційна модель із перевірками цілісності (`PK`, `FK`, `CHECK`). Оновлюється в межах єдиної транзакції (повний зріз / snapshot).
- **audit (Operational metadata):** облік спроб завантаження (`pipeline_runs`), файловий баланс (`run_file_stats`) та карантин невалідних рядків (`rejected_rows`).

## 2. Бізнес-правила та фільтрація дефектів
Кожен рядок джерела класифікується рівно в одну з трьох категорій:
1. **FULL_DUPLICATE:** точна бізнес-копія раніше обробленого рядка. Залишається перший екземпляр, повтори маркуються та ізолюються.
2. **Карантин (Rejected):**
   - `INVALID_PRICE`: товар із `unit_price_uah <= 0` при `is_active = true`.
   - `INVALID_DATE`: дата не відповідає синтаксису або виходить за календарні межі (обробка через `stg.try_cast_timestamptz`).
   - `ORPHAN_CUSTOMER_FK`: посилання на неіснуючого клієнта.
   - `ORPHAN_MERCHANT_FK`: посилання на неіснуючий заклад.
   - `PARENT_REJECTED`: каскадне відхилення позицій замовлень (`order_items`), якщо відповідне замовлення або товар не пройшли валідацію.
3. **Core (Accepted):** валідні записи, що відповідають усім обмеженням домену.

## 3. Нормалізація атрибутів
- Коди валют у `core.orders`: значення `"UA H"` нормалізується до канонічного `"UAH"`.
- Необов’язкові поля (наприклад, `phone IS NULL`) приймаються без підстановки штучних нулів чи сурогатів.
